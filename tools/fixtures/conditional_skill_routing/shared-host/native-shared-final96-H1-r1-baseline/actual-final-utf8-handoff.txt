**sg-docs** maintient la documentation interne : architecture, gouvernance, contexte, métadonnées et consignes pour les agents. Exemple : documenter une décision technique ou mettre à jour le contexte du projet.

**sg-content** prend en charge les contenus destinés au public : documentation utilisateur, articles et expression éditoriale de la marque. Il vérifie les sources, les affirmations et l’adaptation au public jusqu’à la préparation à la publication. Exemple : rédiger un guide utilisateur ou un article.

Le critère de choix est donc la destination : documentation interne → **sg-docs** ; documentation publique ou contenu pour une audience → **sg-content**.

Contexte de transmission : explication seule, portée par **sg-help**. Distinction étayée par les contrats publics figés `skills/sg-docs/SKILL.md` et `skills/sg-content/SKILL.md`. Aucune modification ni publication effectuée ; aucun contrôle du runtime installé.
