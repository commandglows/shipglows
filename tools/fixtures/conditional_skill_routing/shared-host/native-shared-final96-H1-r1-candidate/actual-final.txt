**sg-docs** s’occupe de la documentation interne : architecture, contexte du projet, gouvernance, métadonnées et consignes pour les agents. Exemple : documenter une décision technique.

**sg-content** s’occupe des contenus destinés à une audience : documentation publique, articles, pages et contenus éditoriaux. Exemple : rédiger un guide utilisateur.

Le critère principal est donc la destination du document : interne pour **sg-docs**, publique ou destinée à une audience pour **sg-content**.
