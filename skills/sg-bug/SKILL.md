# sg-bug

## Mission

`sg-bug` is the public owner for reproducing, repairing, retesting, and closing product defects.

## Scope Gate

Resolve the affected product and surface, then load `$SHIPGLOWS_ROOT/skills/references/intent-to-outcome-autonomy.md`. Own the defect until proportional proof exists; do not ask the operator to schedule reproduction, implementation, or verification stages.

## Required References

Resolve `$SHIPGLOWS_ROOT` through the shared canonical-path doctrine, verify the root and `$SHIPGLOWS_ROOT/skills/003-sg-bug/SKILL.md` exist, then load that canonical engine for the full bug lifecycle. If the root or file is missing, stop with a visible error; never fall back to a sibling runtime path. Treat `003-sg-bug` as an expert/legacy engine, not the public name.

`fix` is the canonical repair mode. `shipglows fix <defect>` is only a short
route to `sg-bug fix <defect>`; this public owner still decides whether the
bounded `106-sg-fix` path is sufficient or the full bug lifecycle is required.

When the affected surface is an Obsidian plugin, load
`$SHIPGLOWS_ROOT/skills/references/obsidian-plugin-workflow.md` before reproduction
or retest. Distinguish build, isolated host load, interaction, diagnostics, and
cleanup; never use a personal vault as implicit proof.

## Validation

Use the selected lifecycle's reproduction and retest proof before closing a defect.

## Stop Conditions

Stop and follow the runtime contract when the defect, authority, affected surface, or required proof is unresolved.

## Report Modes

Load `$SHIPGLOWS_ROOT/skills/references/reporting-contract.md` before reporting; keep internal engine names out of user-facing reports.
