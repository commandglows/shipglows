# Redaction Context And Governance

Read the complete available project overview, branding, business, author/founder, technical guidelines, inspiration, source, content-map, claim-register, page-intent, and content-schema authorities relevant to the target. Missing business or brand truth limits specificity; missing author truth blocks invented first-person experience.

Before choosing a public article/blog/newsletter surface, load `skills/references/editorial-content-corpus.md`. Before changing runtime content, schemas, public docs, skill contracts, or mapped technical surfaces, load `skills/references/technical-docs-corpus.md`. These shared references are selected independently by their own gates.

Use an existing declared collection, route, extension, taxonomy, and author convention. If multiple materially valid surfaces remain, ask one targeted question. If none is declared, report `surface missing: blog` and do not invent a path.

Application content follows its local schema. ShipGlows business/editorial artifacts require compatible governance frontmatter. Record business/brand dependency versions in accepted fields; otherwise report them as context versions and metadata gaps. Bump an existing artifact version major for strategic promise/audience changes, minor for substantive new content structure or sources, and patch for corrections. Never force ShipGlows fields into an incompatible runtime schema.

Report relevant `Editorial Update Plan`, `Claim Impact Plan`, and `Documentation Update Plan` outcomes; use a reasoned no-impact result only when that surface truly did not change.
