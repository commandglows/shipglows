# Redaction Quality And Reporting

Before completion, verify language and accents, brand/author voice, factual support, source proximity, copyright-safe synthesis, technical examples, links, heading flow, actionability, frontmatter validity, declared surface, and absence of placeholders or invented claims. Validate the project content schema or build when practical.

Load `skills/references/content-quality-rubric.md` for a near-final draft. Report its verdict honestly: failed source, claim, schema, authorship, or surface criteria block `ready` even when prose is polished.

For `report=user`, name the created files, topics/formats, principal sources or proof, quality verdict, and any remaining gap concisely. Include context versions or metadata gaps plus relevant editorial, claim, and documentation plan outcomes. For explicit detailed handoff, add word counts, target audience, keywords, validation run, and blocked criteria. Do not reproduce a large decorative report template.
