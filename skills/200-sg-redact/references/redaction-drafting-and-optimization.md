# Redaction Drafting And Optimization

Write an original article in the project's language and voice. Open with the reader's problem, stakes, or outcome; make headings useful when skimmed; keep paragraphs focused; explain why each recommendation matters; and end with a concrete next action. Editorial format may use first person only when author truth supports it.

Use the existing content directory, extension, frontmatter schema, taxonomy, author naming, and date conventions. Generate a readable slug and metadata only where the schema accepts them. Never add a placeholder image or unsupported field that breaks the collection.

Support material claims with nearby links. Use concrete examples and executable code only when verified. Quote sparingly, synthesize sources, avoid keyword stuffing, fake urgency, generic filler, unsupported superlatives, and copied structures. Add internal links only to real relevant pages. CTAs must be a natural extension of reader value and must not introduce an undeclared offer or claim.

Optimize title, description, heading hierarchy, answer-first passages, semantic sections, accessibility, and scannability without distorting the article. Add FAQ, HowTo, Article, or other structured data only when the page content and project implementation genuinely satisfy that schema. Do not invent ratings, credentials, reviews, or author experience for E-E-A-T signals.
