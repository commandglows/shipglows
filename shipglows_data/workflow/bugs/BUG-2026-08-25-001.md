# Bug Record: BUG-2026-08-25-001

## Summary

- Title: OWASP contract test reads UTF-8 files with the Windows CP-1252 default
- Current status: `closed`
- Severity: `medium`
- Owner: Diane
- Next command: `none`

## Reproduction

- Preconditions:
  - Windows default text encoding is CP-1252.
  - Repository contract files contain UTF-8 bytes not decodable as CP-1252.
- Steps:
  1. Run `uv run --with pyyaml --with pillow python -m unittest tools.test_owasp_application_security_contract`.
  2. Run without `-X utf8`.
  3. Observe `UnicodeDecodeError` in the consumer-file reads.

## Expected Behavior

- The contract module reads repository UTF-8 text consistently and passes without requiring an interpreter-wide encoding override.

## Observed Behavior

- Two subtests failed before the fix because `Path.read_text()` used the Windows CP-1252 default and could not decode byte `0x8f`.

## Evidence

- Pre-fix command: `uv run --no-project --python 3.14 --with-requirements tools/test-requirements.txt python -m unittest tools.test_owasp_application_security_contract` -> 2 errors, 1 passing test.
- Failing files: `skills/102-sg-start/SKILL.md` and `skills/106-sg-fix/SKILL.md`.
- Fix scope: four `Path.read_text()` calls in `tools/test_owasp_application_security_contract.py`.
- Post-fix focused command: `uv run --no-project --python 3.14 --with-requirements tools/test-requirements.txt python -m unittest tools.test_owasp_application_security_contract` -> 3 tests passed.
