# Bug Record: BUG-2026-08-23-003

## Summary

ShipGlows already installed and validated Chromium for its managed Playwright runtime, but Flutter Web had no `CHROME_EXECUTABLE` mapping and therefore considered the Chrome toolchain unavailable.

## Expected Behavior

- A runnable managed Playwright Chromium path is returned by the installer runtime probe.
- The full installer persists that exact path in `CHROME_EXECUTABLE` for the user and current process.
- The Flutter supervisor forwards only an existing executable under the managed Playwright root and rejects reparse paths.
- Explicit `web-server` mode remains independent of a browser executable.

## Fix and Proof

The installer now exposes the validated full browser path and the supervisor revalidates it before launching Flutter's `chrome` device. Playwright's matching headless-shell executable provides bounded version evidence because the full Windows GUI executable does not implement a terminating console `--version` probe. Static contracts and focused supervisor path tests cover managed acceptance, external-path rejection, and browser-free `web-server` mode.

The second live branch bootstrap persisted `CHROME_EXECUTABLE` to the existing managed `chromium-1234\chrome-win64\chrome.exe`. After refreshing the current process environment, `flutter doctor -v` recognized Chrome, listed the Chrome web device, and reported no issues. The supervisor regression also passed while preserving the two pre-existing `ENVIRONMENT.md` changes.

## Next Step

Closed. A future live managed Flutter Web launch remains a separate product smoke, not a missing installer-fix proof.
