# Bug Record: BUG-2026-09-02-003

## Summary

- The fast Windows launcher removed the established Gum experience and made project selection appear broken.
- The repair keeps `s.exe` as the first process, renders the complete Gum-style root menu natively, and reserves bundled Gum for dynamic project pickers whose options are transported as exact process arguments.

## Closure Criteria

- Bare `s` displays the Gum-style native root menu without starting CMD or PowerShell first.
- `C/G/S/T/R/L/O/K/D/N/A/F/P/U/Q` dispatch the displayed actions immediately without Enter; arrows and Enter select the highlighted action.
- Starting a child action clears the prior root menu; its diagnostics remain visible and exactly one fresh interactive root menu renders below them on return.
- Start, stop, restart, logs, open, unregister, and navigate retain dynamic project discovery through actual Gum pickers.
- Cancel returns safely and unavailable Gum falls back without losing command access.
- The operator confirms the restored rendering and interaction in their terminal.

None. The installed menu passed focused regression and runtime interaction checks, and the operator confirmed the final rendering and keyboard behavior. Command execution latency is outside this bug and remains separate work.
