# Bug Record: BUG-2026-08-24-003

## Summary

The Windows CLI autonomy defects observed while onboarding CommunityGlows were repaired and verified through the installed runtime: dependency setup, process detachment, readiness, durable state, stop behavior, and environment inference now satisfy the bug contract.

## Reproduction

- Run dependency setup for an npm project with `package-lock.json`; npm receives `c i` rather than `ci`.
- Start a Vite surface whose native process exits under Windows Application Control; readiness waits for a generic timeout and the CLI exits zero.
- Register a surface with a durable `ENVIRONMENT.md` port; the registry remains on port zero.
- Run `env inspect`, `plan`, `verify`, and `status` on CommunityGlows; only Linux Flox is discovered, capabilities are empty, and non-ready commands exit zero.

## Expected Behavior

- Native dependency arguments preserve token boundaries.
- A dead process fails quickly with a bounded, redacted, actionable stderr cause and a non-zero CLI exit.
- Registration hydrates a non-colliding durable port; stop is idempotent, quiet, and clears stale live errors.
- Windows identifies incompatible Flox explicitly, infers Node/pnpm and Tauri/Cargo without installing anything, and returns semantic non-zero status while required capabilities are non-ready.
- Truly unmanaged empty projects remain valid.
