# Windows root menu startup

## Summary

Typing `s` waits for managed PowerShell startup, module imports and a capability
snapshot before opening the static fzf root menu. Diane reports about five
seconds; the local reproduction measured about one second, which she also
considers too slow. The five-second observation remains unconfirmed.

## Reproduction

In a Rio/Herdr PowerShell pane, type `s`. The installed command resolves to
`.shipglows/runtime/bin/s.cmd` and opens fzf with the existing fifteen options.

## Expected Behavior

The static root menu appears promptly; project actions retain the managed
PowerShell backend and its validation.

## Evidence And Diagnosis

- Managed PowerShell process startup: 405 ms.
- DevServer and RuntimeStatus imports: 168 ms combined.
- Capability snapshot serialization, validation and replacement: 140 ms.
- Installed interactive menu start inside Herdr: 1218 ms without a shell
  profile, 988 ms using the ordinary pane shell.
- Discovery and version refresh run in child processes and do not explain a
  synchronous five-second delay.
- No credentials or raw account/provider output is retained.

## Fix Attempts

The first native menu attempt moved PowerShell initialization to every choice.
Diane rejected that behavior. A persistent backend reduced later choices but
left the first handoff at 1211 ms.

The current implementation starts a session-bound backend while the native
menu is visible and reuses it for subsequent choices. A user-restricted named
pipe waits for completion without starting another foreground PowerShell host.
The worker monitors its dedicated CMD parent before handoff; Quit or parent
termination stops initialization and removes the temporary channel. A validated
single-character request and accepted marker prevent replay after action start.

Authentication lists tool names without probing every provider. Only the selected
provider is queried in its existing action menu. Name-only project pickers read
the prepared catalogue without reconciling all running processes; a selected
project still passes authoritative identity and registration validation.
Commands with arguments and missing-fzf fallback keep the existing backend.
