# Bug Record: BUG-2026-09-02-002

## Summary

- Title: Windows CLI startup still takes seconds because `s` launches PowerShell
- Current status: `closed`
- Severity: `high`
- Owner: Diane
- Next command: none

## Reproduction

- Preconditions:
  - ShipGlows Windows runtime installed with the managed PowerShell runtime.
- Steps:
  1. Resolve `s` with `Get-Command s`.
  2. Invoke `s h` or open the bare `s` menu.
  3. Measure elapsed time and inspect the spawned process chain.

## Expected Behavior

- `s` resolves to a native executable and renders its initial menu in under one second without starting CMD or PowerShell before a choice is made.

## Observed Behavior

- `s` resolves to `s.cmd`, which starts a new managed `pwsh.exe` and parses the PowerShell DevServer entrypoint before displaying anything.
