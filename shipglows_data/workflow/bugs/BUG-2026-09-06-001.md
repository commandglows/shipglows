# Bug Record: BUG-2026-09-06-001

## Summary

- Title: Flutter supervisor exits when its atomic state replacement meets a Windows reader
- Current status: `closed`
- Severity: `high`
- Owner: Diane
- Next step: keep authenticated login and protected-access validation separate from this supervisor defect

## Reproduction

- Preconditions:
  - Windows and an existing `state.json`.
  - A reader holds the file with read/write sharing but without delete sharing.
- Steps:
  1. Hold `state.json` open with `[IO.FileShare]::ReadWrite`.
  2. Ask the Flutter supervisor atomic writer to replace the state.
  3. Observe the Windows sharing violation at `File.Replace`.

## Expected Behavior

- A short-lived reader does not terminate the supervisor; the state is published atomically after the reader releases it.
- A persistent lock fails within a bounded interval and preserves the previous valid state.

## Observed Behavior

- `File.Replace` immediately raised a sharing violation and terminated the supervisor before Flutter Web became ready.

## Evidence

- Before repair, `tests/windows/flutter-state-atomic.ps1` failed with the same Windows `File.Replace` sharing exception as the durable DevServer stderr.
- After repair, the focused regression, Flutter supervisor protocol suite, and Flutter startup ownership suite pass.
- The two repaired source artifacts were copied locally into `C:\Users\Diane\.shipglows\runtime\bin` with source/runtime hash equality after a managed stop; the prior installed copies remain recoverable under `C:\Users\Diane\.shipglows\backups\flutter-state-lock-20260906-1452`. This was a focused local promotion, not a full official installer or release.
