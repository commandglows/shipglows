# Bug Record: BUG-2026-08-24-002

## Summary

The accumulated dependency setup transcript can contain mixed encoding and NUL bytes on Windows PowerShell 5.1, reducing the reliability of setup diagnostics. Current inspection confirms the file state, but neither the emitting run nor attribution to `Tee-Object` has been isolated yet.

## Reproduction

- Preconditions:
  - Windows PowerShell 5.1.
  - A project whose dependency setup writes through the DevServer setup-log path.
- Steps:
  1. Run the dependency setup path that records `setup.log`.
  2. Inspect the resulting bytes and decode the log as the runtime diagnostics reader does.
- Current result: inspection found NUL bytes and mixed encoding in the accumulated log; the emitting run remains unknown.

## Expected Behavior

- `setup.log` uses one documented encoding, contains no NUL bytes, and remains readable by startup diagnostics.

## Observed Behavior

- Current inspection of the accumulated live log contains NUL bytes and mixed encoding; those bytes may be historical.
- `Tee-Object` under Windows PowerShell 5.1 is the leading suspected boundary, not yet a proven root cause.

## Evidence

- Redacted live-replay observation: after dependency setup completed, the accumulated `setup.log` contained NUL bytes and mixed encoding; no evidence yet distinguishes newly emitted bytes from historical content.
- No raw project log or credential-bearing content is retained in this record.
