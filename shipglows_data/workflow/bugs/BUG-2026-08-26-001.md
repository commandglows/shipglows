# Bug Record: BUG-2026-08-26-001

## Summary

The Windows clone action treats repository cloning and ShipGlows project
preparation as one operator operation. Before this repair, a registration error
was reduced to a warning and the command returned success even though the
project had not been prepared.

## Reproduction

- Run `Register-SgClonedProject` with `Register-SgProject` forced to throw.
- Observe that the warning says the clone was not registered.
- Observe that no terminating error reaches the top-level command handler.

## Expected Behavior

- Preserve the successfully cloned repository.
- Return a non-zero command result when registration or preparation fails.
- Include the clone destination and original preparation cause in the error.

## Observed Behavior

- The clone remains in the workspace, but the preparation failure is swallowed
  and the combined command reports success.

## Evidence

- Proof path: `regression-first`.
- Reproduction: in-memory extraction of the production function with a
  synthetic registration failure.
- Redaction: synthetic paths and messages only; no credentials or private data.
