# Bug Record: BUG-2026-08-23-002

## Summary

The Windows full installer treated any runnable managed Flutter SDK as permanently complete. Repeated installations therefore preserved an old detached commit instead of converging the ShipGlows-owned checkout to the current official stable revision.

## Expected Behavior

- Only `%LOCALAPPDATA%\ShipGlows\flutter` is eligible for automatic update.
- The official `stable` ref resolves to an exact commit, is fetched as `origin/stable`, and a local `stable` branch tracks it.
- A non-official origin or tracked local changes stop convergence without overwriting work.
- Failed validation after checkout restores and revalidates the previous revision.
- Valid external Flutter SDKs are reused but never updated.

## Fix and Proof

The installer now implements that bounded transaction for both fresh and repeated managed installs. Regression proof covers the existing-SDK path, exact stable refspec, named branch, and automatic rollback. Parser and wider Windows contracts pass; live installer and project-build verification remain pending.

## Next Step

Rerun the corrected branch installer, confirm a named `stable` branch at the resolved official commit, then execute locked dependency resolution, analysis, tests, and `flutter build windows` without editing the application lockfile.
