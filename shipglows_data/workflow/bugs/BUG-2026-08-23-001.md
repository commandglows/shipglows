# Bug Record: BUG-2026-08-23-001

## Summary

- Title: Validated Flutter SDK skips PATH activation and overstates Windows readiness
- Current status: `closed`
- Severity: `high`
- Owner: Diane
- Next action: none; retain the regression gates

## Reproduction

- Preconditions:
  - A valid managed Flutter SDK exists under the ShipGlows local tool directory.
  - Its `bin` directory is absent from the persistent user `PATH`.
- Steps:
  1. Run the full Windows installer again.
  2. Let the installer discover and validate the existing SDK.
  3. Inspect the persistent user `PATH` and the generated Windows readiness summary.

## Expected Behavior

- Every validated managed Flutter SDK converges its `bin` directory into both the persistent user `PATH` and the active installer process.
- Windows desktop readiness is `yes` only when Flutter/Dart, Visual Studio Desktop C++, and Windows Developer Mode are all ready.
- A diagnostic does not classify a momentary Flutter cache replacement as durable SDK corruption from one missing-file snapshot.

## Observed Behavior

- The existing-SDK branch returned before PATH convergence.
- The generated Windows readiness field reflected Visual Studio alone.
- A concurrent diagnostic observed `dart.exe` during Flutter's cache replacement and reported the SDK as incomplete even though it later validated successfully.

## Evidence

- Redacted local state: Flutter 3.41.7 and Dart 3.11.5 validate by absolute path; persistent user `PATH` lacks the managed Flutter `bin` directory.
- The environment summary predates the later Dart cache replacement, confirming that install-time readiness and current runtime state are distinct facts.
