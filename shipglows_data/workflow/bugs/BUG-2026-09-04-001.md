# Managed Flutter Windows startup regression

## Expected behavior

A managed `flutter run -d windows` session becomes `running` only after a matching `app.started`. Any startup failure preserves actionable diagnostics, terminates every strictly attributed process, and retries at most once for the known transient debug-connection failure.

## Observed behavior

The Debug executable could remain alive after Flutter reported a stopped log reader before `app.started`. The wrapper then allowed registry reconciliation to report `running` for a stale session, and a later stop could not prove the stale process identity.

## Diagnosis

- Registry reconciliation promoted any live wrapper without consulting supervisor state.
- Extinction checks covered Flutter web listeners and browsers but not the native Windows Debug runner.
- The Job Object termination result was ignored on readiness failure.
- Durable diagnostics omitted the last machine event, Flutter exit code, and exit reason.
- The same fixed 90-second deadline covered both debug attachment and an explicitly active cold Windows build, so a healthy long compile could be terminated prematurely.
- The first progress-aware repair retained the original attachment deadline, so completing a long build could trigger an immediate timeout before VM Service connected.
- Extinction returned on the first empty process snapshot, allowing a late runner to escape cleanup and lock the next build output.

## Fix attempt

- Require supervisor `running` state and an app identity during reconciliation.
- Attribute the native runner from the project's exact `BINARY_NAME`, Debug runner path, and launch time.
- Stop and prove extinction of native runners before clearing process identity or retrying.
- Preserve detailed supervisor diagnostics.
- Retry the known transient debug-connection failure once after verified cleanup.
- Preserve the bounded attachment deadline, but allow an active Flutter build up to ten minutes and fail immediately if its supervisor exits.
- Reset the bounded attachment deadline when active build progress finishes.
- Require a stable extinction window and reap strictly attributed processes that appear during it.

## Proof path

`evidence-first`: focused PowerShell contract tests followed by a controlled managed ContentGlows Windows cold-start and reload retest.
