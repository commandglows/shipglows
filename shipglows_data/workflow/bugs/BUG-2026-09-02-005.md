# Bug Record: BUG-2026-09-02-005

## Summary

- The Windows full-runtime updater declares three native launchers as managed payload files even though the installer generates them inside the transaction action.
- The transaction therefore rejects a valid staged payload before the launcher compiler can run.

## Reproduction

- Preconditions:
  - Use the linked ShipGlows maintainer channel on Windows.
  - Start from a clean checkout whose full payload contains launcher source but no precompiled launchers.
- Steps:
  1. Run `s update`.
  2. Let the bootstrap stage the full Windows runtime.
  3. Observe transaction prevalidation before the installer action.

## Expected Behavior

- Staged files are activated atomically, the installer generates the native launchers, generated targets are verified, and the managed manifest is committed only after success.

## Observed Behavior

- The update stops before mutation because `bin/s.exe` is listed as managed but absent from the staged payload.

## Evidence

- Reproduction output: `Staged runtime file is missing: bin/s.exe`.
- Source inspection: launcher compilation occurs in `install-devserver.ps1`, which is invoked only inside the transaction action.

## Verification

- 2026-09-02 17:07:10 UTC: standard verification passed. The transaction regression proves generation, post-action verification, staged-source refusal, byte-for-byte rollback, idempotence, and unmanaged-path refusal. The Windows update contract, required-gate ownership contract, PowerShell parser, metadata lint, and real linked `s update` also passed.
- Success behavior: a payload without precompiled launchers activates and records the launchers after the installer generates them.
- Error behavior: missing staged input, missing generated output, and exceptions after generation leave the prior runtime byte-for-byte intact.
- Residual behavior: `s update` may warn that its currently running `s.exe` is locked; `shipglows-dev.exe` and `sg.exe` update in the same run, and the warning directs a later `shipglows update` outside `s` to refresh that final launcher.

## Closure Criteria

- A generated managed path may be absent from the payload and must exist after the action.
- Missing generated output or an action exception restores the runtime byte-for-byte.
- Ordinary staged paths still fail before mutation when absent.
- Repeated successful activation remains byte-idempotent and concurrent activation remains locked.
- The real `s update` path no longer fails on a missing staged launcher.
