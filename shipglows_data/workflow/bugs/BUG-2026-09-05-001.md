# Bug Record: BUG-2026-09-05-001

## Summary

Short managed Flutter target changes must allow the supervisor to finish its
documented stop request, and regression tests must verify application output
without relying on npm's choice of log stream. The repair is delivered separately from local runtime activation.

## Reproduction

1. Have the supervisor return a valid stop/open response after nine seconds.
2. Invoke the current stop/open IPC client with the eight-second caller budget.
3. Run `tests/windows/devserver-start-detach.ps1` with managed PS7 and npm 12.

## Expected Behavior

Accept a response within the supervisor's ten-second machine stop budget.
Detached stdout/stderr are readable while the descendant remains live, the CLI
and capture streams return within five seconds of readiness, and managed stop
proves process and service extinction.

## Observed Behavior

The IPC client expired before the supervisor's request budget. The integration
test tried to decode null because its stdout file was empty. That fixture only
wrote stderr and depended on npm's lifecycle banner for stdout.

## Evidence

- Deterministic stop/open IPC polling test failed with `Flutter supervisor stop command timed out` before the fix and passed after it under PS7 and PS5.
- Original detached integration reproduced `UTF8.GetString(null)`; preserving the empty byte array exposed `stdoutBytes=0, stderrBytes=126`.
- Installed npm 12 `@npmcli/run-script/lib/run-script-pkg.js` emits its lifecycle banner through `log.notice`, not application stdout.
- A separate short-parent/detached-child fixture emitting both streams passed on the unchanged runtime, rejecting the initial buffering hypothesis.
- Two subsequent integration attempts hit the old 45-second setup/readiness deadline under load, with npm setup taking 10-19 seconds. The readiness budget now matches the manager's 90 seconds; five-second detachment assertions remain unchanged.
