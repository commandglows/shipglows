# Bug Record: BUG-2026-08-24-001

## Summary

- Title: Capture tool ignores the linked ShipGlows developer root on Windows
- Current status: `closed`
- Severity: `medium`
- Owner: Diane
- Next command: none

## Reproduction

- Preconditions:
  - Windows user has a valid `%USERPROFILE%\.shipglows\development-channel.json` linked to the developer clone.
  - `SHIPGLOWS_ROOT` is absent from the already-running process.
- Steps:
  1. Run the public-repository and fixture path protection tests.
  2. Let `shipglows_root()` resolve the root without manually injecting `SHIPGLOWS_ROOT`.
  3. Observe the resulting refusal code.

## Expected Behavior

- The capture tool resolves the valid linked developer clone and returns `public_repo_target` for output inside that public repository.

## Observed Behavior

- The tool fell back directly to `%USERPROFILE%\.shipglows\runtime`, so the generic Git-repository guard returned `git_repo_target` first.

## Evidence

- Pre-fix: `PathAndSchemaTests.test_path_refuses_shipglows_public_repo` and `PathAndSchemaTests.test_path_fixture_requires_system_temp` both failed with `git_repo_target`.
- Diagnostic control: both tests passed when `SHIPGLOWS_ROOT` was explicitly set to the linked clone.
- Post-fix focused module: `uv run --no-project --python 3.14 --with-requirements tools/test-requirements.txt python -m unittest tools.test_capture_design_inspiration` -> 33 passed.
- Post-fix complete suite: `uv run --no-project --python 3.14 --with-requirements tools/test-requirements.txt python -X utf8 -m unittest discover -s tools -p 'test_*.py' -q` -> 756 passed, 4 skipped.
