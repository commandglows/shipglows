# Title

Industrial excellence quality doctrine

# Status

Reviewed.

# Minimal Behavior Contract

Make industrial-grade delivery the shared completion baseline. Apply critical-system rigor proportionally to consequence, and apply award-caliber visual craft to brand and marketing surfaces without sacrificing product utility, accessibility, performance, or maintainability.

# Success Behavior

- Merely functional, unintentionally generic for the accepted product, fragile, cluttered, or unresolved provisional work presented as final cannot be reported complete.
- Engineering addresses applicable failure modes, observability, recovery, performance, compatibility, migration, security, and maintainability.
- `future-proof` means bounded evolution evidence, not speculative abstraction.
- Brand and marketing sites target distinctive award-caliber craft; operational interfaces remain clarity-first and professionally refined.
- NASA, government, ANSSI, RGAA, SecNumCloud, or similar claims require a framework-specific scoped audit against named requirements and direct evidence.

# Error Behavior

The doctrine fails when it rewards polish over accessibility or performance, equates complexity with robustness, treats generic automation output as excellence, or permits unsupported certification claims.

# Scope In

- shared decision-quality baseline
- implementation, clean-code, design, and excellence-verification doctrine
- scenario-first contract tests and proportional repository validation
- technical documentation and conservative refresh trace

# Scope Out

- public skill renames or invocation changes
- formal compliance certification
- application implementation or redesign
- mandatory aerospace process for low-risk work

# Acceptance Criteria

- [x] Shared baseline blocks merely functional or draft-quality completion.
- [x] Engineering doctrine defines proportional critical-system rigor and observable resilience.
- [x] Design doctrine distinguishes award-caliber brand craft from operational UI clarity.
- [x] False future-proof and compliance claims are explicitly rejected.
- [x] Focused tests, metadata, graph, budget, audit, and public runtime sync checks pass.

# Implementation Tasks

- [x] Define scenario-first pressure tests.
- [x] Update shared and specialist quality contracts.
- [x] Update technical ownership documentation and refresh trace.
- [x] Run conservative refresh, verification, and closure.

# Pressure Scenarios

- `INDUSTRIAL-001 MERELY-FUNCTIONAL`: a passing happy path with fragile failure behavior remains partial.
- `INDUSTRIAL-002 FUTURE-PROOF-THEATER`: speculative layers without a proven evolution pressure are rejected.
- `INDUSTRIAL-003 CRITICAL-RISK`: high-consequence work requires explicit failure, recovery, observability, and security evidence.
- `INDUSTRIAL-004 BRAND-CRAFT`: a generic template-like brand site fails the visual excellence gate.
- `INDUSTRIAL-005 OPERATIONAL-CLARITY`: an operational UI is not forced into spectacle and remains clarity-first.
- `INDUSTRIAL-006 ACCESSIBLE-CRAFT`: visual ambition cannot weaken accessibility, performance, conversion, or maintainability.
- `INDUSTRIAL-007 COMPLIANCE-CLAIM`: named institutional standards require their own scoped audit and evidence.

# Risks

The main risk is replacing vague excellence with vague superlatives or indiscriminate process weight. Every gate must remain observable, proportional, and compatible with compact progressive activation.
